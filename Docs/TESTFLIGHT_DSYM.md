# TestFlight / App Store: ошибки Upload Symbols (dSYM)

## «Не удалось установить… недоступно или не существует»

Чаще всего в **App Store Connect → сборка → Основные → Минимальная версия iOS** стоит **слишком высокое** значение (например **26.2** из‑за совпадения с номером **SDK** в Xcode). Тогда **ни один телефон с iOS ниже этой версии не может поставить билд** — TestFlight показывает ошибку установки.

**Исправление:** в Xcode → проект → **iOS Deployment Target** поставьте реальное требование (**17.0**, **16.0** и т.д.), пересоберите **Archive**, загрузите **новый build** (увеличьте **Build** в General).

В этом репозитории в `project.pbxproj` для проекта задано **IPHONEOS_DEPLOYMENT_TARGET = 17.0** (раньше ошибочно было 26.2).

---

## Что происходит (dSYM)

При загрузке сборки Xcode / App Store Connect ожидают **dSYM** (отладочные символы) для каждого **встроенного бинарного** фреймворка. У предсобранных библиотек **Veepoo / JL** (`ABParTool`, `GRDFUSDK`, `JLDialUnit`) и у вашего **`ZipZap.framework`** в комплекте часто **нет** dSYM — поэтому и появляется предупреждение с UUID.

## Важно

- Это **не всегда блокирует** публикацию в TestFlight: проверьте статус сборки в **App Store Connect**. Часто приложение всё равно обрабатывается.
- Без dSYM **ваш код** в отчётах о сбоях по-прежнему символизируется (если dSYM приложения загружен). Не хватает только **строк внутри чужих** фреймворков.

## Что сделать по шагам

### 1. Папка для dSYM в проекте

Создайте (или наполните) каталог:

`TamyrFlow/Vendor/dSYMs/`

и положите туда bundle’ы:

- `ABParTool.framework.dSYM`
- `GRDFUSDK.framework.dSYM`
- `JLDialUnit.framework.dSYM`
- `ZipZap.framework.dSYM`

Подробности — в **`Vendor/dSYMs/README.md`**.

### 2. Veepoo / JL

Напишите в поддержку **Veepoo** (или откуда брали SDK) и попросите **dSYM для текущей версии** этих трёх фреймворков. Без них предупреждения для них не исчезнут полностью.

### 3. ZipZap

Пересоберите фреймворк из `Vendor/zipzap-source` в **Release** для **устройства** и скопируйте сгенерированный `ZipZap.framework.dSYM` в `Vendor/dSYMs/`. UUID в dSYM должен совпадать с тем, что в сообщении об ошибке (`dwarfdump --uuid`).

### 4. Автокопирование при Archive

В проекте добавлен скрипт **`Scripts/copy_vendor_dsyms.sh`**: при архивации он копирует все `Vendor/dSYMs/*.dSYM` в папку dSYM архива.

Если скрипт не срабатывает из‑за **User Script Sandboxing**, в Xcode: таргет **TamyrFlow → Build Settings → User Script Sandboxing = No** (для этого таргета уже выставлено в проекте при необходимости — см. `project.pbxproj`).

### 5. Firebase Crashlytics (если используете)

В настройках загрузки символов иногда есть опция **не прерывать сборку** при отсутствии части dSYM — зависит от версии плагина.

---

**Итог:** для полного исчезновения предупреждений нужны **официальные dSYM от поставщика Veepoo/JL** + **свой dSYM для ZipZap** из пересборки исходников.
